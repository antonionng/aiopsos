# Experrt educational copy

Write as a knowledgeable trainer explaining the subject to an adult learner. The reader should understand what they are learning, why it matters and what to do next without guessing. Use natural, connected sentences and enough context to make each explanation useful.

## Introduce the learning experience

At the start of a course or preview, explain the subject in plain language, who the material is for, what the learner will practise and what they will produce. State whether it is a preview or a complete course. Explain how to navigate the lessons, answer questions and keep work. Present course availability, pricing and certificate status accurately, using learner-facing language rather than internal production terms.

For introductory courses, assume no prior understanding of agents. Define specialist terms at first use with a concrete example. An agent brief is a set of instructions describing the work, information, limits and expected result. A final practical project is clearer on first use than an unexplained 'capstone'. Preserve technical accuracy as the course becomes more advanced.

## Use a trainer's voice

- Explain cause and effect in connected prose. Avoid chains of short statements such as 'Make decisions. Test boundaries. Build something useful.'
- Use descriptive headings that identify the topic or activity. Avoid slogans such as 'Different tools. Useful outcomes.'
- Use short labels for navigation and diagrams where brevity helps. Do not turn every explanation into a fragment or pad sentences simply to make them longer.
- Speak directly to the learner using 'you'. Be respectful, practical and encouraging without hype or exaggerated praise.
- Name the actor, document and action when a pronoun or generic word could be ambiguous. Explain what is being checked and which information establishes the answer.
- Introduce fictional organisations and explain the documents they use. Mark sample data and illustrative calculations clearly.
- Use British English. Do not use em dashes.

## Prefer everyday language

Write the way a helpful trainer would explain a task aloud to someone learning it for the first time. Start with a familiar action and example: “Choose a task you do every day or week, such as preparing a report.” Do not assume learners already know the language of agent operations or course assessment.

Prefer concrete verbs such as choose, write, check, try, fix and explain. Name the person, file or action instead of using abstract nouns. Simpler wording should preserve the reason, practical steps and useful detail; it should not turn the course into short slogans or speak down to adults.

Examples for this platform:

| Instead of | Prefer |
| --- | --- |
| Choose a responsibility worth delegating | Choose a task you do every day or week |
| Write a brief an agent can execute | Write clear instructions for your agent |
| Connect context and set authority | Choose what your agent can see and do |
| Define acceptance conditions | Explain what a correct result should include |
| Configure a cadence | Choose when the task should run |
| Inspect the artefact | Open the result and check it |
| Reconcile completed effects | Check which steps have already happened |
| Retain your evidence | Keep your work and a record of your checks |
| Prepare a bounded pilot | Try it on a small example first |

Keep necessary product names, code terms and assessment requirements accurate. Introduce a technical term only when it helps the learner use a tool or understand a rule, and explain it beside a familiar example. For instance, explain a trigger as what starts the task before using the product's “trigger” label.

Review the complete journey, including module names, lesson paragraphs, answer feedback, diagrams, field labels, downloads and public course descriptions. Read the wording aloud: would a learner understand the action and its purpose without having to translate it? Improve the sentence if they would not.

## Teach through activities

Introduce the situation before asking for a decision. State the learner's role, relevant facts and the decision to make. Keep every scenario understandable without relying on an earlier lesson being read. Give plausible choices that test the taught distinction; do not make the answer depend on an unstated policy.

Feedback should explain why a choice helps or causes a problem and what the learner should do next. Use 'This approach...' rather than unexplained judgements such as 'Good judgement' or 'Consider the consequence'. Preserve the correct-answer mapping during copy edits.

For practical exercises, explain the task, the expected deliverable and how the learner can check it. Define terms such as test log, reviewer or evidence when they first appear. Label form fields by what the learner should write and give examples or descriptive help.

Explain assessment as a process: what to submit, what a reviewer checks, how feedback and resubmission work, and when a certificate can be earned. Distinguish practice progress from assessed competence without repeating warnings in every paragraph.

## Examples from this repository

Instead of: 'Give your agent a job. Learn to run it well.'
Use: 'Learn the foundations of working with always-on AI agents.'
Follow with an introduction explaining that these agents can continue agreed work between conversations and that the preview teaches task selection, instructions, checking results and handling problems.

Instead of: 'A draft says two projects are overdue. One is complete and the other has no due date. What should you do?'
Use: 'You are reviewing the weekly project report prepared by the agent for Northstar Studio, a fictional design business. The report lists two projects as overdue, but the project tracker shows that one is complete and the other has no recorded due date. How should you check the report before sharing it with the owner?'

Instead of: 'Output and acceptance tests. Specify format, source references and observable success conditions.'
Use: 'What should the agent produce, and how will you check it? Describe the output you need and the checks you will use to decide whether it is correct. For a weekly report, you might require a link to each project record and a separate list of missing information.'

## Review before finishing

Read the edited page in order, including headings, questions, feedback, form help and downloads. Check whether a first-time learner can explain what the page does, how to use it and what the next step is. Remove unexplained jargon, slogan-like fragments and ambiguous references. Preserve useful instructional depth and factual limitations.

Apply the same wording standard to diagrams and downloadable resources within scope. Check layout after expanding text, especially mobile navigation, choice cards and diagram labels. Validate behaviour if an edit changes interaction or assessment data. For the always-on agent series, consult docs/always-on-agent-course-standard.md for agreed learning depth and assessment requirements; do not turn proposed course features into claims that they already exist.

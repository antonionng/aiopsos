## Narration

As of 9 October 2026, narration uses OpenAI `gpt-realtime-2.1-mini`, the built-in `marin` voice, a natural British English accent and a gentle, unhurried delivery for ages 4–6. This is the replacement recommended in [OpenAI's text-to-speech deprecation notice](https://developers.openai.com/api/docs/deprecations). Authored scripts are recorded through the Realtime WebSocket API during publishing, then encoded to MP3. The UI explicitly identifies narration as AI-generated.

The current library contains 406 authored scripts covering instructions, projects, feedback, explanations of the AI learning purpose and animated demonstrations. Superseded clips remain for cache compatibility. No child profiles, answers, free text or saved work are sent to OpenAI. Audio is generated during publishing and served as local static assets; runtime playback never calls a generation endpoint or consumes a child's generation allowance. Playback does not substitute the device's speech voice if a recording is unavailable. A clear message offers another attempt or the on-screen instructions. Turning voice off or navigating stops pending playback.

## Animated teaching

The four free games include narrated, four-step demonstrations, with captions, pause, replay and manual stepping. Each phase advances when its recorded narration ends. Robot Rescue shows an incorrect route and a revised route; Creature Creator shows replacing an unsuitable feature; Prompt Repair Shop demonstrates the effect of unsupported instructions; Launch Studio shows claim correction and removal. Reduced motion disables movement and retains the narrated steps and captions. Demonstrations do not award progress or stickers.

Every mission also states the skill being practised and how it helps with AI. The route game explicitly distinguishes following fixed commands from AI learning patterns, and explains that clear instructions do not guarantee correct AI output. The listings continue to address parents and lead with developmental benefits.

The final production build, TypeScript and targeted ESLint passed. Thirty Wonderlab and public-route tests passed, including complete narration asset coverage and a narrowly scoped public MP3 route. Browser checks confirmed real MP3 playback, all four narrated demonstrations advancing through their four phases, the younger demonstration ending cleanly, and no rewards being awarded by watching it. Mobile checks at 390px found no horizontal overflow, with demonstration controls at least 44px tall. The illustrated listing cards were visually reviewed. No browser errors were reported. Family testing and human review of educational suitability remain launch requirements.

Regenerate from the repository root using `node --env-file=.env.local --experimental-strip-types scripts/generate-wonderlab-narration.mts`. Use `--dry-run` to inspect pending work and `--limit=3` to sample. This command incurs provider usage only for missing clips. The script uses six workers, checks each returned transcript against its script, and retries failed or mismatched recordings up to three times. Transcript comparison accepts punctuation differences and equivalent spoken numbers, but rejects changed or added words. It preserves completed clips after a failed request; rerunning resumes. API keys stay in the publishing environment. `ffmpeg-static` is a publishing dependency only. Bump `NARRATION_VERSION` before changing voice or delivery, so cached older voices cannot be reused. Updating script text creates a new asset ID automatically. Retain old clips for previously published content versions.

# Atomic learning agent results

10 September 2026.

The credit-hold path now completes each execution through `lms_complete_agent_result`. In one transaction it stores an immutable result keyed by execution lease, updates the task for review where still authorised, and settles actual usage. A failed settlement rolls back the result and task update. Exact completion retries return the existing disposition; different content or usage is rejected. A lost acknowledgement is retried once in the same worker without calling the model again.

Completed results from cancelled tasks, replaced workers or revoked owners are retained in a service-only table and do not overwrite current task state or grant access. Late output after an abandoned reservation was released is retained without rebilling, with a reconciliation note. A course/programme without a proposal records its explanation as failed rather than claiming it is ready for review. Human review and application remain required.

The transaction removes the previous settlement-before-output gap. It cannot preserve output if the process dies before its first database write or the database stays unavailable through both save attempts. It does not checkpoint partially generated tokens or partially executed tool loops. Retained output has no self-service restore UI yet. These are explicit remaining recovery gaps, not claims of exactly-once provider execution.

# Experrt reviewer calibration and decision record
Read the course-specific expected results as well as the common assessment guide. Evaluate the learner's files and results, not the appearance of the report or the practice percentage. Require independent explanations of the consequential decisions.

## Review sequence
1. Identify learner, course version, attempt, evidence locations and whether the demonstration is live or simulated.
2. Inspect brief, actual permissions and source snapshots before assessing the output.
3. Check one final claim or behaviour independently and inspect an exception test.
4. Replay or inspect the practice problem and check actual effects for duplicates.
5. Ask the course-specific changed-case question. Record the learner's explanation and any assistance given.
6. Score each dimension separately, with an evidence reference and improvement action. A score below 3 in any dimension returns the attempt for revision. Do not compensate through averaging.
7. Record the decision and require a verified certificate workflow after a pass; never issue from browser practice progress.

## Calibration examples
- Attractive output, but no source or test evidence: verification 0 or 1 depending on what can actually be inspected; return the work.
- Correct normal output, but a missing field is silently guessed and needs prompting to fix: verification 2; require an independently explained missing-data case and retest.
- Complete permission table, but an external message is sent without required approval: authority 1; investigate the actual effect, restore the boundary and require a fresh demonstration.
- Correct checks, tested boundaries and recovery, with independent explanation: score 3 where the evidence meets each criterion.
- Same competent evidence plus a tested improvement on unseen cases with measured cost and documented limits: score 4 for the relevant dimension only.

## Feedback format
Skill: [name]. Score: [0–4]. Evidence: [file/run/case]. Observed: [specific behaviour]. Required improvement: [concrete action]. Reassessment: [case or result to inspect].

## Consistency check
For the AI assessment service, calibrate missing evidence, unsafe behaviour, conflicting instructions and a complete example against this guide. Record model, policy, scores and limits. Live platform demonstrations and learner pilots must be recorded separately; automated checks do not establish those results.

# Course-specific evidence checks

## 1. Find a task that takes up too much time

The pilot prepares checkable information with an accountable business owner.

A small business wants immediate automation of all administrative work. Which initial scope is defensible?

Best response: Choose a regular task where you can check and correct a draft.
This gives you a small task to try before using the agent more widely. Write down how you do it today so you can compare the time and results later.

Alternative: Ask the agent to take over all the work and decide what success means afterwards.
The agent would have to guess what you want and which decisions it may make. Choose one smaller task and describe a correct result before trying it.

Alternative: Choose the task with the biggest possible saving, even if you do not have the information it needs.
A possible saving does not make the task ready to try. First check that you have the information and can tell whether the result is right.

## 2. Get your business records ready

Each row is accounted for; missing contact and duplicate delivery are distinct conditions.

The operations report silently excludes R204 because its contact is absent. How should the record be represented?

Alternative: Fill the gap with the most likely value so the report remains complete.
The inferred value would appear to be a fact. Keep the gap explicit unless the brief authorises and labels an estimate.

Alternative: Remove the affected record from the report without explanation.
Omitting the record hides incomplete coverage. Keep its ID in the exception list and state what could not be checked.

Best response: Report the missing value or unavailable source as a separate exception.
Missing is not zero or a known status. Preserve the gap so that the owner can resolve it without being misled.

## 3. Decide who receives each task and who checks the work

The process prepares useful drafts without granting rights or sending messages.

A complete access request reaches the agent during the pilot. Which response respects the process?

Alternative: Reject all access requests without showing them to the owner.
The policy reserves a decision rather than prohibiting every request. Route it to the accountable owner with supporting information.

Best response: Record the request as awaiting approval and preserve its request ID.
The access category requires the IT owner’s decision. A routing draft can prepare the decision without granting rights.

Alternative: Grant access because all required fields are present.
Valid fields make the request complete, not authorised. Keep the access grant behind the defined approval step.

## 4. Prepare a useful report each week

Five distinct requests are accounted for, with no duplicate R202 route or hidden exception.

The report counts six new requests because it counts rows. What should be checked before accepting the total?

Alternative: Create a new output because each trigger delivery deserves its own response.
Delivery can be repeated for the same intended event. Distinguish deliveries from unique business work.

Alternative: Suppress every similar-looking future item.
Similar items can be legitimate new work. Use stable identifiers and reporting periods rather than vague resemblance.

Best response: Use the existing item ID or run key to check whether the intended output already exists.
Matching the intended operation to its recorded effect prevents a repeated event from becoming new work.

## 5. Deal with repeated tasks and missing information

One R201 record, a traceable policy version and no silent rerouting.

The workflow retries after a lost acknowledgement for R201. Which step prevents duplicate business work?

Alternative: Delete the existing result to make it easier to start again.
The result may contain useful work and help explain what went wrong. Keep it and check what happened before deciding what needs to change.

Best response: Check what has already happened and continue only the unfinished steps.
The agent may have saved a draft before the connection failed. Look for that result and check the task reference before trying again, so you do not repeat completed work.

Alternative: Start the whole task again because it is marked as failed.
The failure may have happened after some steps were completed. Starting again without checking could create a second report or repeat another action.

## 6. Check whether the agent helps and plan a small trial

The recommendation uses equivalent scope and states the limits of the one-week evidence.

The owner wants to turn one successful weekly result into a guaranteed annual saving. What should the analysis include?

Alternative: Compare only the agent’s execution time with all manual work.
This excludes human work required to obtain an acceptable result and overstates the improvement.

Alternative: Convert all saved time into guaranteed cash savings.
Time has value but does not automatically remove a cash cost. Label the assumed rate and explain whether any expenditure actually changes.

Best response: Include preparation, review, correction, maintenance and operating charges.
Value depends on the whole process at an equivalent quality standard. Separate one-off setup from time spent on the regular task.

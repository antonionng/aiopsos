# Experrt reviewer calibration and decision record
Read the course-specific expected results as well as the common assessment guide. Evaluate the learner's files and results, not the appearance of the report or the practice percentage. Require independent explanations of the consequential decisions.

## Review sequence
1. Identify learner, course version, attempt, evidence locations and whether the demonstration is live or simulated.
2. Inspect brief, actual permissions and source snapshots before assessing the output.
3. Check one final claim or behaviour independently and inspect an exception test.
4. Replay or inspect the practice problem and check actual effects for duplicates.
5. Ask the course-specific changed-case question. Record the learner's explanation and any assistance given.
6. Score each dimension separately, with an evidence reference and improvement action. A score below 3 in any dimension returns the attempt for revision. Do not compensate through averaging.
7. Record the decision and require a verified certificate workflow after a pass; never issue from browser practice progress.

## Calibration examples
- Attractive output, but no source or test evidence: verification 0 or 1 depending on what can actually be inspected; return the work.
- Correct normal output, but a missing field is silently guessed and needs prompting to fix: verification 2; require an independently explained missing-data case and retest.
- Complete permission table, but an external message is sent without required approval: authority 1; investigate the actual effect, restore the boundary and require a fresh demonstration.
- Correct checks, tested boundaries and recovery, with independent explanation: score 3 where the evidence meets each criterion.
- Same competent evidence plus a tested improvement on unseen cases with measured cost and documented limits: score 4 for the relevant dimension only.

## Feedback format
Skill: [name]. Score: [0–4]. Evidence: [file/run/case]. Observed: [specific behaviour]. Required improvement: [concrete action]. Reassessment: [case or result to inspect].

## Consistency check
For the AI assessment service, calibrate missing evidence, unsafe behaviour, conflicting instructions and a complete example against this guide. Record model, policy, scores and limits. Live platform demonstrations and learner pilots must be recorded separately; automated checks do not establish those results.

# Course-specific evidence checks

## 1. Decide who is responsible and write down the task

Every consequential decision and exception has an owner and a measurable response.

The agent has produced reports for weeks, but nobody owns missing-field corrections. What change addresses the operating gap?

Best response: Say which information to use, what to produce, how to check it and when to ask for help.
These instructions explain the task clearly. Try an ordinary example and one with missing information to check that the agent knows what to do.

Alternative: Ask the agent to make the result more professional without explaining what is missing.
A more professional tone will not add a requirement the agent does not know about. Explain what the result should include and how you will check it.

Alternative: Let the agent guess what you need from earlier conversations.
Earlier conversations may be incomplete or out of date. Put the important rules in the current written instructions.

## 2. Choose what your agent can see and do

The record shows observed effects and enforceable limits where the environment supports them.

A connected account can edit deadlines, although the brief permits reporting only. How should a proposed edit be handled?

Alternative: Proceed because the connected application technically permits the action.
Technical access is not authorisation. Enforce the agreed rule about what the agent may do and check that no external effect occurred.

Alternative: Treat an earlier approval for another draft as permission for this action.
Approval belongs to particular content and circumstances. A new destination or revision needs a fresh decision under the stated policy.

Best response: Prepare the draft and request approval for the specific action that affects other people or records.
The instruction permits preparation but reserves the external effect for approval. Show the current content, destination and action to the owner.

## 3. Make a set of examples to test your agent

The set covers normal, incomplete, boundary and failure behaviour with work a reviewer can check.

Five easy tests pass, but no permission or interruption case has been checked. What testing approach is needed?

Alternative: Change expected results to match the agent’s latest output.
This removes the independent standard. Investigate the disagreement and change requirements only when the owner explicitly decides to do so.

Best response: Write expected outcomes and check normal, incomplete, boundary and failure cases.
A varied set exposes distinct ways the workflow can fail. Keep expected results independent of the agent’s explanation.

Alternative: Accept a successful demonstration as evidence that every case is covered.
One example does not test missing data, boundaries or interruption. Add cases with known outcomes.

## 4. Fix a failed task without doing the same work twice

One final result, preserved incident evidence and a verified restart condition.

A failure record and an existing output disagree about completion. What should happen before the workflow resumes?

Alternative: Start the whole task again because it is marked as failed.
The failure may have happened after some steps were completed. Starting again without checking could create a second report or repeat another action.

Alternative: Delete the existing result to make it easier to start again.
The result may contain useful work and help explain what went wrong. Keep it and check what happened before deciding what needs to change.

Best response: Check what has already happened and continue only the unfinished steps.
The agent may have saved a draft before the connection failed. Look for that result and check the task reference before trying again, so you do not repeat completed work.

## 5. Track spending, checking time and useful alerts

The recommendation includes total time and cost, alert usefulness and a clear stop condition.

The system sends more messages after a schedule change but detects no additional meaningful events. How should value be assessed?

Alternative: Convert all saved time into guaranteed cash savings.
Time has value but does not automatically remove a cash cost. Label the assumed rate and explain whether any expenditure actually changes.

Best response: Include preparation, review, correction, maintenance and operating charges.
Value depends on the whole process at an equivalent quality standard. Separate one-off setup from time spent on the regular task.

Alternative: Compare only the agent’s execution time with all manual work.
This excludes human work required to obtain an acceptable result and overstates the improvement.

## 6. Check that the task works and explain it to someone else

All six skill areas have evidence and unresolved issues are visible to the next owner.

The audit finds a failed permission test alongside strong scores elsewhere. What assessment decision follows the standard?

Alternative: Award a certificate because every practice activity is marked complete.
Practice progress shows which activities you have worked through. A certificate needs a pass in the practical assessment.

Alternative: Use high scores in other areas to make up for the failed permission check.
You need at least 3 out of 4 in every area. If the permission check is below that score, improve that part and have it checked again.

Best response: Have a reviewer check the work and provide anything still missing.
The reviewer needs to check your skills in every required area. Finishing practice activities and producing a good-looking result are not enough to show that you have passed.

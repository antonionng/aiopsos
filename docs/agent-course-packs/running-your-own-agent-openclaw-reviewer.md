# Experrt reviewer calibration and decision record
Read the course-specific expected results as well as the common assessment guide. Evaluate the learner's files and results, not the appearance of the report or the practice percentage. Require independent explanations of the consequential decisions.

## Review sequence
1. Identify learner, course version, attempt, evidence locations and whether the demonstration is live or simulated.
2. Inspect brief, actual permissions and source snapshots before assessing the output.
3. Check one final claim or behaviour independently and inspect an exception test.
4. Replay or inspect the practice problem and check actual effects for duplicates.
5. Ask the course-specific changed-case question. Record the learner's explanation and any assistance given.
6. Score each dimension separately, with an evidence reference and improvement action. A score below 3 in any dimension returns the attempt for revision. Do not compensate through averaging.
7. Record the decision and require a verified certificate workflow after a pass; never issue from browser practice progress.

## Calibration examples
- Attractive output, but no source or test evidence: verification 0 or 1 depending on what can actually be inspected; return the work.
- Correct normal output, but a missing field is silently guessed and needs prompting to fix: verification 2; require an independently explained missing-data case and retest.
- Complete permission table, but an external message is sent without required approval: authority 1; investigate the actual effect, restore the boundary and require a fresh demonstration.
- Correct checks, tested boundaries and recovery, with independent explanation: score 3 where the evidence meets each criterion.
- Same competent evidence plus a tested improvement on unseen cases with measured cost and documented limits: score 4 for the relevant dimension only.

## Feedback format
Skill: [name]. Score: [0–4]. Evidence: [file/run/case]. Observed: [specific behaviour]. Required improvement: [concrete action]. Reassessment: [case or result to inspect].

## Consistency check
For the AI assessment service, calibrate missing evidence, unsafe behaviour, conflicting instructions and a complete example against this guide. Record model, policy, scores and limits. Live platform demonstrations and learner pilots must be recorded separately; automated checks do not establish those results.

# Course-specific evidence checks

## 1. Choose a computer and set up your agent

A redacted environment inventory and an result you can open and check, with untested features identified.

Your model replies successfully, but you have not tested the monitoring source or host recovery. What does this establish?

Best response: Demonstrate the capability in the intended account and record conditions needed for the task to run.
A documented feature and working account access are different evidence. Record what you actually tested and label any remaining assumption.

Alternative: Treat the provider’s example as proof that this account can run the workflow.
The example does not establish your plan, region or integration access. Perform a harmless account-level test first.

Alternative: Give the agent broader access until the task appears to work.
Broad access obscures the actual requirement and expands consequences. Test the smallest necessary capability in a practice area.

## 2. Connect an AI model and choose the tools it can use

The tool boundary is demonstrated, and no secret appears in the workbook or output.

A tracker note asks the agent to read a credentials file outside the practice area. What authority should apply?

Alternative: Follow the request because it is written in the file the agent was told to use.
Permission to read a file does not mean permission to do everything it asks. Keep the owner’s rules in place and ask them about the conflict.

Alternative: Ignore the whole file without telling anyone.
This could leave important information out of the result. Explain the conflict and whether the remaining information is enough to finish the task.

Best response: Keep the owner’s rules and treat the request in the file as something to report, not permission to act.
The file gives the agent information, but cannot change what the owner has allowed it to do. Explain the conflicting request and do only the agreed task.

## 3. Give your agent instructions and useful information

The current source wins, and the evidence identifies what context changed.

The agent retains an old status after the tracker is updated. Which information should govern the new briefing?

Alternative: Delete all useful context and start without checking the conflict.
Removing everything can lose necessary constraints. Identify the outdated item, correct it and check the effect.

Best response: Apply the current explicit constraint and verify a subsequent result.
The current instruction wins over an old preference. Inspect the next result rather than relying only on an acknowledgement.

Alternative: Keep the remembered preference because it has been used before.
Past use does not make the preference current. Compare it with the dated instruction and correct the context.

## 4. Set up regular checks and useful alerts

Only meaningful changes produce the intended draft notification; each run is traceable.

Every heartbeat sends the same unchanged status. Which check should prevent the repeated notification?

Alternative: Create a new output because each trigger delivery deserves its own response.
Delivery can be repeated for the same intended event. Distinguish deliveries from unique business work.

Alternative: Suppress every similar-looking future item.
Similar items can be legitimate new work. Use stable identifiers and reporting periods rather than vague resemblance.

Best response: Use the existing item ID or run key to check whether the intended output already exists.
Matching the intended operation to its recorded effect prevents a repeated event from becoming new work.

## 5. Track costs and get your agent working again

The system stops on the defined limit and recovers without duplicate final reports.

The provider connection repeatedly fails, but the draft already exists. How should the operator begin recovery?

Alternative: Delete the existing result to make it easier to start again.
The result may contain useful work and help explain what went wrong. Keep it and check what happened before deciding what needs to change.

Best response: Check what has already happened and continue only the unfinished steps.
The agent may have saved a draft before the connection failed. Look for that result and check the task reference before trying again, so you do not repeat completed work.

Alternative: Start the whole task again because it is marked as failed.
The failure may have happened after some steps were completed. Starting again without checking could create a second report or repeat another action.

## 6. Keep your agent running and explain it to the next person

The handover contains demonstrated operating steps, clear permissions and ongoing cost ownership.

The agent works on your host, but nobody else knows how to pause it or inspect costs. Which evidence is still needed?

Alternative: Award a certificate because every practice activity is marked complete.
Practice progress shows which activities you have worked through. A certificate needs a pass in the practical assessment.

Alternative: Use high scores in other areas to make up for the failed permission check.
You need at least 3 out of 4 in every area. If the permission check is below that score, improve that part and have it checked again.

Best response: Have a reviewer check the work and provide anything still missing.
The reviewer needs to check your skills in every required area. Finishing practice activities and producing a good-looking result are not enough to show that you have passed.

# Individual changed-case challenge
Make the source unavailable during a check-in. Demonstrate a failure report with a clear retry limit and a later successful run without inventing a current status.
